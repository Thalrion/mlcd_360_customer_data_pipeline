## Linear task tracking (MLC direct)

Internal tasks for this project belong to [MLCD 360 Customer Data Pipeline](https://linear.app/lule-rheingau/project/mlcd-360-customer-data-pipeline-a1b3ba2c9c2a) in the Linear workspace `https://linear.app/lule-rheingau`, team `MLC direct` (`MLC`). At the start of non-trivial work, use an authenticated Linear connector or MCP client to list issues filtered by `team="MLC direct"` and `project="MLCD 360 Customer Data Pipeline"` (for example, `linear_list_issues`). Search for the request, then fetch the matching issue by identifier (for example, `linear_get_issue`) to read its full scope, status and links. Re-read the issue before changing it, and avoid duplicates. For work spanning projects, inspect the owning project in each team before coordinating updates.

Use an already connected Linear integration first. Other agents can connect to Linear's remote MCP endpoint `https://mcp.linear.app/mcp` with Streamable HTTP and OAuth 2.1 using their own authorized identity; Codex CLI can use `codex mcp add linear --url https://mcp.linear.app/mcp`, and Claude Code can use `claude mcp add --transport http linear-server https://mcp.linear.app/mcp`. Repository access alone does not grant Linear access. Never put tokens, OAuth data, customer data or workspace exports in this repository or issue text.

When the user has authorized implementation, creating or updating the matching Linear issue is part of that work. Otherwise read only. Keep its status aligned with verified progress; code, a green check or a merge alone is not release proof. If Linear is unavailable, report the access gap while preserving incident continuity. Existing repository, operational, safety and deployment instructions still apply.
